# Iteration 20 — политика хранения истории аудитов

Статус: **DONE**

## Цель

Ограничить рост таблицы истории аудитов и сделать очистку старых запусков контролируемой и безопасной.

## Что сделано

- Добавлена команда:

  ```bash
  python manage.py cleanup_ml_audit_history --keep=30
  ```

- По умолчанию команда работает в режиме предпросмотра и ничего не удаляет.
- Фактическое удаление требует явного флага:

  ```bash
  python manage.py cleanup_ml_audit_history --keep=30 --apply
  ```

- Лимит применяется отдельно для каждого курса.
- Сохраняются самые новые запуски; старые записи удаляются вместе с JSON-снимками.
- Некорректный лимит меньше 1 отклоняется с понятной ошибкой.
- Интерфейс истории уже ограничивает отображение последними 30 запусками.

## Проверки

- Dry-run не удаляет записи.
- `--apply` оставляет ровно заданное количество запусков на курс.
- `python manage.py cleanup_ml_audit_history --keep=30` на текущей базе: удалять нечего.
- `python manage.py check` — без ошибок.
- `makemigrations courses --check --dry-run` — изменений схемы нет.
- `python manage.py test courses --keepdb -v 1` — **77 тестов OK**.
